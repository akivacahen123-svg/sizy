# איך בונים היררכיה בבאנר (נלמד מ-14 גדלים שמעצבים עשו ידנית)

המקור: `bench/exemplars/library.json` (4 קמפיינים + 1200×300 של הלקוח). הנתונים נמדדו מהתמונות, לא נכתבו מהראש.
אלו עקרונות, לא קואורדינטות. הם נכנסים לפרומפט של מעצב ה-AI (`src/design.ts`) ולמדד האיכות (`bench/score.mjs`).

## הנתונים
| מדד | מה נמדד ב-14 הגדלים |
|---|---|
| שטח הכותרת מתוך הבאנר | 8%–30%. קטן בבאנר גבוה/גדול, גדל ככל שהבאנר נמוך וצר |
| מיקום אופקי של הכותרת | מרכז (0.47–0.51) בכל הבאנרים הרגילים. רק בפסים צרים מאוד היא זזה לצד |
| כותרת משנה ביחס לכותרת (גובה שורה) | כ-0.4 (טווח 0.23–0.66), תמיד מעל הכותרת |
| שטח הלוגו | 2%–7%, תמיד קטן מהכותרת |
| שטח הכפתור | 1%–5% |
| מיקום הכפתור | בתחתית (גובה 0.75–0.96) בכל הבאנרים שאינם פס; בפס הוא במרכז האנכי |
| גלריית תמונות | בגבוה: מתחת לכותרת, במרכז. ברחב: בקצה אחד (0.77–0.9 לרוחב) |

## החוקים
1. **נקודת מוקד אחת.** הכותרת הכי גדולה והכי בולטת. כל השאר "לוויינים" שמסדרים סביבה, ולעולם לא מתחרים בה.
2. **סולם גדלים קבוע:** כותרת 1 : כותרת משנה ≈0.4 : כיתובים הכי קטנים. הכפתור והלוגו קטנים מהכותרת.
3. **סדר קריאה:** חלק עליון = הקשר (לוגו או כותרת משנה), אחריו כותרת, אחריה הוכחות (תמונות), ובסוף קריאה לפעולה (כפתור). הכפתור תמיד אחרי הכותרת.
4. **באנר גבוה וריבועי:** עמודה במרכז, הכותרת עד כמעט כל הרוחב, כפתור בתחתית.
5. **באנר רחב:** שלושה אזורים. המרכז = כותרת. שני הקצוות = לוויינים (גלריה בקצה אחד, לוגו עם כפתור מתחתיו בקצה השני). בפס צר מאוד: שורה אחת, הכל באמצע האנכי.
6. **מעט גדול עדיף על הרבה קטן.** כשמשהו יוצא קטן מדי (למשל עיגולים), מסדרים מחדש (2×2) או מורידים, ולא מכווצים.
7. **אותו סדר חשיבות בכל הגדלים.** רק הפריסה משתנה.

## איך זה נאכף
- מעצב ה-AI מקבל את החוקים בפרומפט.
- המנוע: בבאנר רחב הגלריה בקצה והלוגו מעל הכפתור, גלריה עוברת ל-2×2 כשהעיגולים קטנים מ-30% מהגובה.
- המדד: דגלים `weak_headline`, `logo_dominant`, `cta_order` (ועוד `hierarchy` הקיים).
